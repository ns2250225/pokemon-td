# 宝可梦守卫战 · Pokémon Tower Defense

2D 卡通风格的策略塔防网页游戏，核心玩法参考《保卫萝卜》，使用宝可梦角色。
**纯前端**（Vue 3 + TypeScript + Vite + Phaser 3 + Pinia），无后端、无登录。

## 功能特性

- **80 个关卡**：8 大主题章节（常青森林 / 海滨小镇 / 火山 / 雪山 / 幽灵古堡 / 沙漠遗迹 / 天空之城 / 冠军之路）× 10 关，全部数据驱动、程序化生成；敌人构成每局从本章图鉴池随机抽取（含波次血量预算护栏，保证任意随机种子下都可通关）
- **1025 只宝可梦**均有战斗配置：防御塔与敌方单位由种族值 / 属性 / 稀有度推导
- **18 属性完整克制表**，倍率经塔防化调整（免疫不归零，防御塔不会完全失效）
- **养成系统**：升级（Lv.1~5）→ 进化（Lv.3 解锁）→ 终极招式（Lv.5）
- **收集系统**：图鉴"遭遇即发现"、章节通关奖励解锁新精灵、宝箱隐藏解锁、异色形态收集
- **BOSS 战**：每章第 10 关，三阶段 + 专属技能（烈焰封锁 / 替身分身 / 龙之冲锋等）
- **敌方特性**：飞行（走直线捷径）、隐身、护盾、治疗光环、召唤、分裂、再生、重甲、高速
- **地图清理**（保卫萝卜式）：击毁路径旁的树木 / 岩石 / 宝箱 / 水晶得金币、额外建造格、增益
- **成就系统**：13 项成就统一判定，与进度联动
- **移动端适配**：横屏优先 + 旋转引导 + CSS 旋转兜底，安全区域适配
- **零音频素材**：音效与 BGM 全部由 Web Audio API 实时合成

## 玩法

### 核心循环
在敌人行进路径旁建造宝可梦防御塔，阻止敌人抵达右侧基地。基地生命归零即失败；
抵御全部波次即胜利。每波通过后发放金币奖励，随波次与关卡递增。

### 星级评价
| 星级 | 条件 |
| --- | --- |
| ★ | 通关 |
| ★★ | 剩余生命 ≥ 50% |
| ★★★ | 剩余生命 100% |

### 操作

| 操作 | 说明 |
| --- | --- |
| 点击建造栏卡片 | 进入建造模式，地图上高亮可建造格 |
| 点击地图格子 | 放置防御塔 / 选中已有塔 |
| `空格` | 暂停 / 继续 |
| `1` `2` `3` | 切换 1× / 2× / 3× 速度 |
| `U` / `E` / `S` | 升级 / 进化 / 出售选中的塔 |
| `ESC` | 取消选中 → 取消建造 → 返回 |

### 精灵解锁与收集
- 初始可用：**妙蛙种子 / 小火龙 / 杰尼龟 / 皮卡丘**
- **章中奖励**：每章第 4、7 关各解锁 1 只、第 9 关解锁 2 只（优先当关建造名单内未解锁的）
- **章尾奖励**：第 10 关 BOSS 通关解锁下一章主题精灵（最多 4 只）
- **宝箱隐藏解锁**：开箱有概率从防御名册中随机解锁一只未解锁的精灵
- **图鉴发现**：战斗中遭遇（敌人出场 / 放置 / 进化）即计入"图鉴发现"
- 全部 80 关通关后解锁传说 / 幻兽

### 属性系统
18 种属性完整克制表，倍率经塔防化调整（避免防御塔完全失效）：

| 关系 | 倍率 |
| --- | --- |
| 克制 | ×1.5 |
| 被抵抗 | ×0.75 |
| 双重克制 | ×2.0（上限） |
| 免疫 | ×0.25（绝对下限，不会归零） |
| 双重抵抗 | ×0.5（下限） |

### 地图清理（保卫萝卜式）
路径旁的树木、岩石、宝箱、水晶会被防御塔的攻击溅射摧毁（命中点周围判定），
清除后获得金币；岩石可能掉落额外建造格，水晶提供全场攻速增益，
**宝箱有概率开出隐藏精灵**。所有障碍物都贴路径生成，保证全部可清理。

### BOSS 战
每章第 10 关为 BOSS 关，BOSS 具备：
- **三个阶段**（100% → 60% → 30% 生命），每次转换强化速度与技能频率并短暂无敌
- **专属技能**，释放前有预警提示：烈焰封锁建造区、替身分身、龙之冲锋、
  精神屏障、天空突袭、暗影领域等
- **专属血条**与特性标签

### 敌方构成规则
- 每章敌人从本章属性池中抽取，保持主题一致性
- **飞行占比 ≤ 40%**（天空之城除外——它反向限制地面单位 ≤ 40%），
  避免"整波需要专门对空 / 对地却无从应对"的硬门槛
- **隐身敌人仅出现在幽灵古堡章**（隐身主题教学章）
- 召唤型敌人有召唤上限与冷却，防止波次有效血量失控

## 两个关键技术决策

### 1. 战斗模拟与渲染解耦（固定时间步长）
速度倍率通过"每帧执行多个固定步"实现，**绝不放大 `dt`**。
因此 1× / 2× / 3× 下伤害、冷却、敌人数量完全一致 —— 倍速不影响平衡。

```
accumulator += min(delta, 100) × speed
while (accumulator >= SIM_STEP_MS) { simulateStep(); accumulator -= SIM_STEP_MS }
```

伤害结算发生在 `simulateStep()` 内，技能动画异步播放不参与结算，
所以掉帧不会改变战斗结果。

### 2. 伤害与动画解耦
`playMove()` 返回 Promise 但不被 `await`——命中时刻由
`castMs + 距离/弹速` 计算并压入 `pendingImpacts` 队列，
由模拟循环在正确的模拟时间点触发伤害。

## 数值平衡

关卡难度通过以下旋钮控制，全部集中在数据层，便于回归验证：

| 旋钮 | 位置 |
| --- | --- |
| 初始金币 / 基地生命 / 波次奖励 | `levels.ts` 关卡生成 |
| 波次数量与出怪间隔增长曲线 | `levels.ts` `buildWaves()` |
| 敌人血量 / 速度 / 击杀奖励 | `units.ts` 推导公式 |
| 章节难度系数 | `WaveSystem.ts` 生成缩放 |
| 召唤上限 / 治疗上限 | `Enemy.ts` / `WaveSystem.ts` |

配套两个调参工具（在 Node 里复用游戏真实战斗代码，与渲染完全解耦）：

```bash
npm run sim:level -- 1-1 good     # 无头仿真某关：casual / good / max 三档玩家水平
npm run report:balance -- 2-5     # 输出某关波次构成、敌我数值、经济测算
```

`sim:level` 会以"认真玩家"策略（覆盖最优布点 + 性价比建造/升级/进化）完整快进
一整关，输出胜负与基地余量——改完数值跑一遍 80 关，即可确认难度曲线没有回归。

## 素材管线

素材全部通过脚本从公开来源获取到本地，并记录来源与授权状态。

```bash
npm run assets:sync-pokemon      # 从 PokeAPI 同步图鉴（1025 种）
npm run assets:download-pokemon  # 下载精灵图 / 立绘 / 异色 / 图标 / 动态图
npm run assets:download-vfx      # 下载粒子素材（Kenney, CC0）
npm run assets:process           # Python 处理：裁剪 / 缩放 / GIF→WebP 图集
npm run assets:status            # 把素材实际状态回写图鉴
npm run assets:manifest          # 生成运行时清单
npm run assets:audit             # 缺失检测 + 授权检查 → docs/ASSET_LICENSES.md
npm run assets:all               # 全流程
```

### 素材覆盖
| 类型 | 覆盖 |
| --- | --- |
| 静态精灵图 | 1025 / 1025（100%） |
| 官方立绘 | 1025 / 1025（100%） |
| 异色形态 | 1025 / 1025（100%） |
| 队伍图标 | 1025 / 1025（100%） |
| 动态图集 | 1008 / 1025（98.3%，其余回退静态图 + 缓动） |
| 特效纹理 | 46 个程序化生成（CC0） |

**音效与 BGM 全部由 Web Audio API 实时合成**（振荡器 + 噪声 + 包络），
零第三方音频素材，因此不存在音频授权问题。

**特效纹理为程序化生成的白色 + alpha 基础纹理**，运行时按属性着色与缩放，
一套纹理覆盖全部 18 种属性的技能表现。

## 测试

```bash
npm run typecheck      # TypeScript 全量类型检查
npm run test:logic     # 85 项核心逻辑断言（属性表 / 伤害 / 选敌 / 关卡 / 单位）
npm run dev            # 另开终端
npm run test:browser   # 浏览器端到端：菜单 → 关卡 → 建造 → 战斗 → 图鉴 → 设置 → 成就
npm run test:battle    # 完整关卡模拟：建塔 → 打完所有波次 → 结算 → 星级
```

`test:logic` 覆盖数据层不变量（18 属性倍率边界、1025 只单位配置合法性、
80 关路径连通性与确定性、目标选择各模式、空间网格查询）。

`test:battle` 通过 CDP 驱动真实浏览器，用 `debugFastForward()` 以确定性方式
跑完整关，断言"胜利 → 结算 → 星级 → 存档写入"整条链路。

### 已知限制
- `test:browser` / `test:battle` 需要本机安装 Edge 或 Chrome（通过 CDP 驱动，不依赖 Playwright）。
- 无渲染的 headless 环境下帧率很低，因此战斗测试使用固定步长快进来推进模拟。

## 移动端适配

**横屏优先**，三级降级策略：

1. **全屏 + 屏幕方向锁定** — 支持 Screen Orientation API 的浏览器直接锁横屏
2. **旋转引导界面** — 锁定失败时引导用户手动旋转设备
3. **CSS 旋转兜底** — 仍为竖屏时把游戏容器顺时针旋转 90°，
   并重映射触摸坐标

安全区域（刘海 / 手势条）通过 CSS 变量 `--safe-*` 处理。
战场内容约束在第 2~10 行的行带内，顶部 HUD 与底部建造栏不会遮挡路径与单位；
矮屏设备下建造栏自动切换紧凑布局。

## 性能

- 空间哈希网格做目标查询，避免 O(塔 × 敌) 全遍历
- 伤害数字与粒子对象池化，避免高频 GC
- 精灵纹理 LRU 缓存（PC 160 / 移动端 80 个纹理）
- 动态图集按需加载，静态图作为回退
- 单只素材加载有超时兜底，缺失时走占位显示而非阻塞开局
